# Governance — 项目简介

> **一句话：** 一个跑在你自己机器上的工程控制面。它把一个想法沿着九阶段研发环路推进，但**不允许任何阶段"声称"自己完成了** —— 阶段状态由磁盘上的产物推导，每个 gate 的决定只能追加进日志，不能改写状态。

- **形态：** 本地 Web 控制台（`127.0.0.1`），加上一个 CLI
- **版本：** 0.1.0，`experimental`
- **技术栈：** TypeScript，**运行时零依赖**（只有两个 devDependencies）
- **代码规模：** `src/` 17 个 TS 文件，约 6 个目录；`web/` 是原生 JS 前端；`test/` 219 条断言

---

## 1. 它是什么

大多数"AI 帮你写代码"的工具，优化的是**产出速度**。Governance 优化的是另一件事：**你能不能证明某个阶段真的发生过。**

它做的事很具体：

1. 从磁盘上读你的研发工作区（纯 Markdown，`.scratch/<effort>/`）；
2. 把读到的产物推导成九个阶段的状态；
3. 把需要人拍板的地方呈现为 gate；
4. 你每一次通过、退回、跳过，都作为一行记录追加进 `decisions.jsonl`；
5. 全过程不拥有你的数据，只投影它。

```
intake → ask → spec → design → split → develop → review → ship → retro
```

`design` 刻意放在 `spec` 和 `split` 之间：切片是**依赖接口**排出来的，接口没定就切片，切出来的片子一定会重写。它可以被跳过，但只能用 `**Design:** none - <理由>` 这种写法跳过 —— 让"跳过"成为一条**有记录的决策**，而不是一次疏忽。

## 2. 它解决什么问题

用 agent 写代码，产出很容易，但有三件事会悄悄失控：

| 失控点 | 常见后果 | Governance 的做法 |
|---|---|---|
| **状态靠人点** | 看板上的"已完成"是一句声明，和磁盘上的东西对不上，最后变成第二个互相矛盾的真相来源 | 阶段状态**从产物推导**，纯函数，不打勾 |
| **审批靠记忆** | 谁在什么时候批准了什么，没人说得清；改一次状态，审计链就断了 | gate = 不可变定义 + 只追加的决策日志，日志是唯一权威 |
| **缺口被抹平** | `design` 从没做过，但 `split` 的票已经开了一堆，系统显示一切正常 | **crossed 只报告，不吸收** —— 明确告警，不把缺口折叠成"完成" |

第四条同样重要：**整个产品里没有任何百分比。** 九个阶段上的一个百分比，暗示了一种这个环路并不具备的精度。所以只显示离散的阶段状态。

### 一个真实案例

第一次拿它去扫一个真实仓库（`railyard` 的 `methodology-view` 分支），输出是：

```
methodology-view   +++>>>>.   3/9  at design  13 tickets  all resolved
! stage "split"  has output but "design" was never satisfied (crossed)
! stage "develop" has output but "split"  was never satisfied (crossed)
```

这不是解析 bug。票确实开了、活确实干了，但没有任何一份 `design` 产物被声明过 —— 链路有个真实的缺口，工具把它说了出来，而不是替人抹平。**这就是这个产品存在的理由。**

## 3. 产品形态

### 一个进程，三个命令

| 命令 | 作用 |
|---|---|
| `governance scan [root...]` | 读工作区，打印阶段、票、告警；`--json` 给机器读 |
| `governance serve [--port N]` | 起本地 UI + API（默认 4173），前台运行 |
| `governance advance <effort>` | 规划下一阶段要跑的 skill；**默认 dry run**，加 `--execute` 才真的启动 |

### 界面里有什么

- **Portfolio overview** —— 多仓库、多 effort 的总览，谁被 gate 卡住一眼能看到
- **Pipeline rail** —— 九阶段 + 每阶段对应的 skill；skill 被停用或机器上没装，**直接标出来**
- **Vertical slice board** —— 票按**阻塞图的深度**排成列，不用任何人手工排序
- **Gate 面板** —— 通过 / 退回重做 / 跳过并记录，每个动作带证据指针
- **Inbox** —— 还欠人一个决定的地方
- **Settings** —— agents、skills、MCP、credentials、git、automation
- **中英双语** —— 整套 UI 与文案都是双语的

### 两分钟演示（无需任何凭证）

```bash
npm install
npm run serve:demo     # http://127.0.0.1:4173
```

`--demo` 用脚本化的 agent 跑完整流程：输入一句模糊的想法 → 一轮问题 → 一份 PRD 落盘。它写的每一个字都会标明"这是 demo 产出的"，**不会**被误当成真实会话。真实模式是 `npm run serve`。

## 4. 新项目从哪里开始

```
idea  →  rounds  →  prd
```

这是整个产品最"agentic"的一段，也是最克制的一段：

- 你只输入**一句模糊的话**，原样送入，不做整理 —— 模糊本身就是原料。
- 中间那一步由 `/grill-with-docs` 这个 skill 驱动。**应用里没有任何一行"该怎么提问"的逻辑**，提示词只说明读哪个 skill 文件、需要什么格式回来。
- 每一轮返回的是**问题 + agent 自己会给出的答案**，全部同意就是一键通过。
- 前沿（frontier）没清空之前，**拒绝生成 PRD** —— 提前冻结会锁死那些还没被问到的问题。
- 每个 effort **一条会话**（`claude --resume`），中断、关电脑、第二天回来，从同一轮继续。
- 每一轮都是磁盘上的产物（`.session/NN.json`），不是一个正在消失的聊天窗口。

写出来的东西：

```
.scratch/<effort>/
  spec.md                  PRD
  GLOSSARY.md              术语，边聊边沉淀
  docs/adr/                每个决策一个文件
  .session/state.json      会话 id、进行到哪
  .session/NN.json         每一轮，应用直接渲染
  .session/turns/          每一句提示与回复，原文
```

## 5. 架构

```
markdown on disk  →  parser  →  domain model  →  HTTP API  →  UI
```

| 目录 | 职责 |
|---|---|
| `src/domain/` | `types.ts` 领域模型；`stages.ts` 阶段推导（**纯函数**，无文件系统、无时钟、无配置） |
| `src/tracker/` | `parse.ts` 解析 Markdown；`discover.ts` 扫盘；`decisions.ts` 只追加日志；`scaffold.ts` 脚手架 |
| `src/server/` | `http.ts` loopback API + 静态资源（每次请求重读磁盘，不缓存） |
| `src/exec/` | `runner.ts` 每阶段一次 headless CLI；`resolve.ts` 跨平台定位 CLI；`demo.ts` 脚本化 agent |
| `src/session/` | 提问会话：轮次、提示词、状态推导、重置 |
| `src/config/` | `settings.ts`，带校验，未知字段原样保留 |
| `web/` | 原生 JS + 双语 i18n；`api.js` 是唯一的"领域模型 → 视图模型"适配层 |

### 三个值得说的技术取舍

**1. 应用里没有 stage 的提示词。** 每个阶段只是把 skill 文件的路径和工作目录交给 agent。协议只有一份，就是那个 skill 文件；应用里再写一份，两份迟早会漂移。

**2. 状态是纯函数推导出来的。** `deriveStages(facts)` 不碰文件系统、不看时钟、不读配置，所以规则可以被直接测试，也无法偷偷和磁盘上的事实不一致。

**3. 不编造任何数值。** 不知道的东西 —— 几个 agent 在跑、CI 什么状态、花了多少 token —— 字段留空，界面就不显示。**在一个治理看板上放一个"看起来合理"的数字，比留白糟糕得多。**

## 6. 边界：它明确不做什么

这些不是"还没做"，是设计本身。去掉任何一条，这个产品的性质就变了。

| 边界 | 原因 |
|---|---|
| **只监听 loopback** | 没有网络面，所以也不需要认证；不会有第二个用户 |
| **前台运行，无定时器，无文件监听** | 进程退出就什么都不在跑。它会变成一个"后台自己刷新的看板"，那就成了它不该是的托管服务 |
| **只写 effort 自己的 `.scratch/`** | 服务端从不接受客户端传来的路径；gate 引用解析后要再次校验仍在工作区内；有专门的路径穿越测试 |
| **不制造新的真相来源** | Markdown 永远是权威，`serve` 每次请求重读，不缓存。**过期的看板比慢的看板更糟** |
| **不执行部署** | 部署在这里被批准、被记录；执行留在外面 |

## 7. 现状：验证到什么程度

跑一遍 `npm test`，五道门：

| 门 | 覆盖 | 结果 |
|---|---|---|
| 单元断言 | 解析、阶段推导、决策日志、设置校验、会话、CLI 解析 | **219 / 219 通过** |
| Web 无头启动 | 整页渲染 + 页面上**每一个 inline handler 都可调用** | 通过 |
| 会话 e2e | 真 socket、脚本化 agent、重置与恢复 | 通过 |
| Demo e2e | 真 socket，完整 idea → rounds → PRD | 通过 |
| 页面自检 | 文案与状态一致（含"不该出现的话必须不出现"的反向断言） | 通过 |

几个刻意的验证选择：

- **对真实语料测，不只对 fixture 测。** 解析器是照着磁盘上一个真实的 13 票 effort 写的，机器上有它就跑。
- **真实文件系统、真实 socket。** 包括四条"试图用 gate id 逃出工作区"的穿越尝试。
- **失败要分类，不能合并。** CLI「没装」「装了跑不起来」「跑了但没登录」「被宿主拦了」「限流」「没拿到 session id」是六种状态、六种应对。合并成一个 `available: false` 是曾经的 bug，现在有断言守着。

### 已知缺口（明说，不藏着）

- **GitHub 镜像** —— 本地 Markdown 权威，镜像延后，将来也只能单向出，不能成为第二个权威
- **Gate SLA 超时升级** —— 没有定时器可挂，字段存着，不假装在跑
- **阶段运行历史进 UI** —— `runs/*.log` 和 `turns/*.log` 已经在写，记录视图还没读
- **并行 agent 调度** —— `maxParallel` 存了、显示了，但一次只跑一个阶段
- **真实 CLI 在本机无法执行** —— 沙箱拦截了 `reg.exe`。所以 runner 是一个可注入的 seam，它之上的一切都用脚本化替身测过；探针会分别报告「装了吗」和「能跑吗」

## 8. 怎么向别人介绍

### 30 秒版本

> 这是一个本地的工程控制面。它不帮你写代码更快，它帮你**证明**流程真的走过了。九阶段环路，每个阶段的状态是从磁盘上的产物推导出来的，不是点出来的；每个 gate 的批准只能追加进日志，改不了。所以它永远不会变成第二个和现实不一致的看板。它甚至在你自己的仓库里找出过一处"没做设计就直接开了票"的真实缺口 —— 而且只是报告，没有替你抹平。

### 两分钟版本

1. **痛点**：agent 让产出变便宜了，也让"这步到底做没做"变贵了。
2. **机制**：状态靠推导，审批靠日志，缺口靠报告。三条都不依赖人的自觉。
3. **形态**：一句模糊的想法进去，问几轮，PRD 落盘；之后每个阶段跑哪个 skill、卡在哪个 gate，都在一个本地页面上。数据始终是自己的 Markdown。
4. **证据**：219 条断言、五道测试门、真 socket 的端到端；demo 模式不用任何凭证就能看完整流程。
5. **边界**：单人、本地、前台、无认证 —— 因为它就不是一个托管服务。

### 常见提问

**「这和 Jira / Linear 有什么区别？」**
Jira 记录**人声明**的状态；这里记录**产物证明**的状态。票在 Jira 里"完成"是有人拖了一下；在这里，`review` 完成是因为 `reviews/*.md` 存在。前者需要信任，后者可以核对。

**「那不就是个看板？」**
看板是它的界面，不是它的主张。主张是：状态不可声明、审批不可覆盖、缺口不可抹平。把这三个拿掉，界面还在，产品没了。

**「能多人用吗？」**
不能，而且这是故意的。没有账号、没有租户、没有权限检查 —— gate 上的"角色"只是标注"谁应该批"，不是 enforceable 的权限。**做一个假的权限检查，比承认没有权限更糟。**

**「数据在哪？」**
在你自己的 `.scratch/` 里，纯 Markdown。工具可以整个换掉，不需要迁移。**数据比工具活得久。**
